队列面板：不再单独做深色皮肤

上一版把播放页的队列改成了深色，理由是「跟沉浸播放页保持一致」。实际用起来，同一屏里「队列」是黑的、「更多」是浅的，两个弹层两套皮肤，反而更乱。现在统一：所有展开列表都跟随系统主题。

一句话：队列面板的配色交回给主题，和「更多」、歌单、搜索结果用同一块卡片。 面板底色 palette(isDark).bg，不再有 dark 强制开关。播放页本身仍是沉浸深色，变的只是它弹出来的面板。

改了什么

位置改动
QueueSheet删掉 @Prop dark 强制深色开关，调色板回归 palette(this.isDark)
QueueSheet根节点继续自己铺 this.p().bg（这版 SDK 上 bindSheet 的 backgroundColor 不生效，必须自带底）
PlayerPageQueueSheet({ dark: true }) → QueueSheet({ ... })，跟随主题
PlayerPagebindSheet 底色在 panel 4 时同步为 palette(this.isDark).bg，圆角处不再漏一圈封面暗色
PlayerPage新增 @StorageProp('isDark')：页面本身仍 palette(true) 沉浸深色，弹层却要读真实主题

为什么播放页的 p() 不能直接改

播放页整页压在封面模糊图上，文字必须用近白 + 暗阴影，所以它的 p() 恒为 palette(true)。面板是另一层皮：它有自己的不透明底，应该按系统主题取色。这也是给 PlayerPage 单独引入 isDark 的原因。

深色主题下会怎样

系统深色时 isDark = true，队列自动变成 #0B0C10 深卡片，跟全站深色列表一致；浅色时就是 #F5F6F9。一个面板只有一套逻辑，不再有「这个页面特殊」的分支。

自检怎么防回退

AB 组规则已反向改写：以前查「有没有传 dark」，现在查「有没有偷偷加回 dark 或改用固定深色」。

# AB：面板要自己铺不透明底色，且跟全站同一套主题 if 'backgroundColor(this.p().bg)' not in q: # 必须自带底 if "backgroundColor('#00000000')" in q: # 不许透明 if '@Prop dark' in q: # 不许强制深色 if 'palette(this.isDark)' not in p_body(q): # 必须跟随主题 if 'dark: true' in player_page: # 播放页不许传 if 'this.panel === 4 ? palette(this.isDark).bg' not in player_page: # 圆角不漏边

反向验证过：把 @Prop dark 和 palette(this.dark || this.isDark) 加回去，立刻报 2 条 FAIL；撤回后恢复 PASS。
