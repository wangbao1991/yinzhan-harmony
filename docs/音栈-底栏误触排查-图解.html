点「发现」却进了播放页

不是阴影。是收起态那条看得见的播放坞，在展开时变成了一层看不见的播放坞，正好压在三个标签上。

一、先看现象和位置对不对得上

用户的原话是「只有设置最边缘那一点能触发」—— 374 正好是播放坞的右边界，越过去才轮到标签栏自己。

二、病灶：HitTestMode.None 只关自己，不关子树

层展开时的视觉展开时的命中
展开态三格标签可见✓ 正常
收起态播放坞opacity 0，完全看不见✓ 照样吃点击

原写法是 .hitTestBehavior(collapse() > 0.45 ? Default : None)。
None 的语义是「这一层自己不参与命中」，不是「整棵子树都不参与」。 播放坞里的封面、歌名、三个控制键仍然各自响应——于是透明的一层把标签栏整条盖住了。

阴影为什么不是原因

.shadow() 只参与绘制（radius 18、offsetY 8），不进入命中测试树。 投影再长也点不到。真正的问题是布局上完全重叠：两层都是 width('100%')， 同一个 Stack，后写的那层在上。

四、改了什么

改动作用
const FORM_SWITCH = 0.34
两层互补的 .enabled()		 展开层 collapse < 0.34、收起层 collapse ≥ 0.34，同一条线切分，不留「谁都能点」的空窗。enabled 会连整棵子树一起关，这才是真正的「这一层不在场」。
MiniPlayer 的 live() 守卫 进播放页 / 播放暂停 / 下一首 / 队列四个回调，紧凑版在 bar < 0.34 时直接 return。万一某台机器上 enabled 没按住，也还有这一道。
外壳那条播放条：高度收到 0 后 .enabled(false) 它为了保住淡出过渡留在树上，里面仍是 58 高的一整套控件。clip 只裁绘制、不裁命中，不关掉就是底栏上方一条看不见的「点哪都进播放页」。
