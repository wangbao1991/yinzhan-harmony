二、四种列表的删除，语义完全不一样

它们共用同一个详情页和同一套 swipeAction，所以动作必须按 kind 分发 —— 借用别人的分支，就会悄悄改到别的地方。

列表左滑实际影响一键清空
我喜欢移除Library.removeFavorite：只改收藏表✓ 确认后
最近播放移除Library.removeHistory：只改历史（按「歌名+歌手」键）✓ 确认后
本地音乐删除local.remove + 摘掉队列里的那条（文件没了，留着会报错）✗ 等于删光导入的文件
自建歌单移除removeFromPlaylist：只动歌单，文件不动✗ 误删整份歌单的代价太大

收藏 / 历史这两条路径都不碰播放队列：取消收藏不等于不想听，把正在播的那首从队列里抽掉会直接打断当前播放。

三、清空要过确认

清空我喜欢

将移除 128 首收藏。只清空这个列表，不会删除本地文件，也不影响已下载的歌。

取消清空

为什么清空是图标、不是文字按钮

这一行已经有「播放全部 / 随机 / 下载全部」，392 的屏再塞一个 60 宽的文字胶囊就会换行。 破坏性操作靠确认弹窗把关，不靠按钮做得多大。

清空后 songs、封面、计数一起归零，空态补一句「还没有收藏歌曲，在播放页点心形按钮即可」， 不会停在一片白屏上让人以为页面坏了。
