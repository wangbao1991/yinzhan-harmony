搜索「歌手」头像空白 · 诊断与修复

音栈 v2.12（versionCode 23 / 2.12） · 2026-11-07 · 依据 5 张真机截图 + 4 个平台接口实测

结论：不是深色模式把图变黑了，而是头像 URL 根本没被取出来，加上占位渐变用了 ArkUI 不解析的 hsl() 字符串，两层叠加后每个歌手只剩一个纯色圆圈和白色 ♪。接口实测大多本来就有头像，是代码丢掉了。

一、现象：五个源，同一个结果

搜索源结果数量头像位置对应原因
酷我0（「没有找到歌手」）—searchArtists() 没有酷我分支，直接返回空数组
QQ1（陶喆）空圆 + ♪avatar: '' 硬编码
网易云9（含卢广仲、范玮琪…）空圆 + ♪avatar: '' 硬编码
酷狗3（陶喆 / 景陶喆 / 陶喆(2)）空圆 + ♪搜索接口不返回 imgurl
咪咕1（陶喆，浅色模式）空圆 + ♪搜索接口不返回 img

网易云那张出来 9 个名字，是从「相关歌手」搜索结果里按名字去重得来的，不是 9 张专辑。

二、定量证据：圆圈里一点颜色都没有

对结果区（避开状态栏、搜索框、播放条）逐像素统计：

97~99.8%深色图近黑像素占比
99.8%浅色图近白像素占比
0.00%三张图的「明显彩色」像素
≈ 0圆圈中心 RGB 标准差

首个圆圈中心的 RGB 均值是 [0,0,0]（深色）/ [255,255,255]（浅色），标准差≈0 —— 纯色，没有任何渐变。而 Cover 组件本应画一层按种子生成的彩色渐变：它把 hsl(...) 字符串直接传给 ArkUI 的 linearGradient，该属性不解析 hsl 格式，整块底色不渲染，只剩外层那圈 0.8vp 描边和白色 ♪。所以「黑底」是占位层没画出来，深色模式只是提供了黑背景。

三、三层根因

1 · 数据层：接口有图，代码没取

四个接口都是本轮直接请求的真实返回：

  • QQ smartbox_new.fcg 的 data.singer.itemlist[].pic 有现成头像 http://y.gtimg.cn/music/photo_new/T001R150x150M000...jpg，TxSmartItem 也声明了 pic，但 txSearchArtists() 写死 avatar: ''。
  • 网易云 type=100 的 result.artists[] 带 img1v1Url（1:1 方图）和 picUrl，但 WyArtist 接口只声明了 id/name，avatar 同样写死空。
  • 酷狗 /api/v3/search/singer 实测只回 singername + singerid，imgurl 不存在；真头像在 /api/v3/singer/info?singerid=… 的 imgurl（带 {size} 占位）。
  • 咪咕 search_all.do 的 singerResultData.result[] 实测只有 id / name / highlightStr，无图。
  • 酷我 未实现歌手搜索；其公开接口 search.kuwo.cn/r.s 返回单引号非标准 JSON，JSON.parse 会失败。

头像 URL 全部实测无防盗链、可直接 GET 200：QQ https 化后 5.3KB、网易云 img1v1Url 1.2MB、酷狗 fixCover 替换 {size}→240 后 13.9KB。

2 · 渲染层：hsl 渐变不生效

见上一节。Cover 在 uri 为空时走 Text('♪')，而它下面的渐变 Column 因为颜色格式非法而整块透明。

3 · 产品语义：这些圆圈是歌手头像，不是专辑封面

artistList() 用 Cover({ side: 88, radius: 44 }) 画的是圆形歌手头像，专辑封面在工程里是方形卡片（GlassSheetCard，kind='album'）。两者形状、组件、数据来源都不同。

四、修复对照

平台v2.11v2.12

网易云avatar: ''补 WyArtist.img1v1Url/picUrl，取 img1v1Url 优先（1:1 方图适合圆头像）

酷狗的一个坑：按 singerid 拼 singerimg.kugou.com/uploadpic/softhead/400/.jpg 看起来能 200，但实测 3 个不同 id 下载到的文件 MD5 完全相同（同一张兜底图）——会让所有歌手变成一张脸。所以必须走 singer/info 的真实 imgurl，其路径带日期且每个歌手不同。

Cover 组件

// 新增：无图时用歌手名首字，而不是清一色的 ♪
@Prop fallbackText: string = '';

// 新增：占位渐变改为十六进制（ArkUI 不解析 hsl 字符串）
colors: [[placeholderGradient(this.gradientSeed())[0], 0],
         [placeholderGradient(this.gradientSeed())[1], 1]]

Text(this.badge.length > 0 ? this.badge
   : (this.fallbackText.length > 0 ? this.fallbackText : '♪'))

placeholderGradient() 用 FNV-1a 按歌手名生成色相，输出 #RRGGBB（抽样：陶 → #b5684a / #807f2d，陶喆 → #4aa5b5 / #2d3a80），亮度压在中等区间，白色首字清晰可读，深色下也不再是黑圈。搜索列表与歌手详情页都传了 fallbackText，详情页顺便去掉了有图时多余的 ♪ 角标。

seededGradient() 原有的 hsl 返回值继续用于播放页与歌单卡片的渐变。

五、「一般搜歌手出来的应该是专辑吧？」

答复搜「歌手」分类出来的是歌手卡片（头像 + 名字），这是 QQ 音乐、网易云等主流 App 的通行做法；专辑是另一个独立分类。点进歌手卡片进的是歌手主页，展示热门歌曲，专辑通常在主页里单独成区。

本工程的具体结构是：

  • 搜索页只有「单曲 / 歌单 / 歌手」三个 tab；SearchType 里虽然定义了 ALBUM = 3，但没有启用，search() 的 else 分支会把 3 也当歌手搜。
  • 专辑数据其实存在：QQ smartbox 的 data.album.itemlist[].pic 有专辑封面，txSearchAlbums() 目前只作为「歌单接口不可用时的兜底」混入歌单结果，条目 kind='album'，由 SheetDetailPage 承接。
  • ArtistPage 目前只列热门歌曲（SongRow）+ 播放全部 + 搜同名歌手，没有专辑区。

所以「应该出专辑」的直觉指向的是工程缺一个专辑入口 / 歌手页缺专辑区，而不是歌手搜索结果做错了。本次改动只作用于头像的取图与占位渲染；搜索分类结构为三个 tab、歌手页列热门歌曲，专辑数据以 kind='album' 存在于歌单详情页链路中。

七、客观边界

  • 酷我切到该源仍显示「没有找到歌手」：其公开接口返回单引号非标准 JSON，本版没有引入自定义解析，避免解析失败把搜索页整块带崩。
  • 咪咕接口不提供歌手图，显示歌手名首字的彩色色块，不会出现真人照片。
  • 当前为 OpenHarmony 公共签名，正式 HarmonyOS NEXT 真机仍需 AGC 证书；API 26 包最低只能装 API 26+ 设备。
  • 专辑能力在工程中以 kind='album' 与 txSearchAlbums() 存在；搜索页为三个 tab，ArtistPage 列热门歌曲。
