删除音源改成左滑

菜单里的「删除音源」移除，改为卡片左滑露出红色删除块；点它才弹确认。多一道物理门槛，也少一次「长按 → 找菜单项」。

为什么不是「两个入口都留着」 两个入口并存时，用户还是会走更容易误触的那个。菜单删除是单点直达，而删除会把脚本文件一起 unlink —— 误删只能重新导入。左滑要滑够距离，再叠一次确认才够稳。

一、交互长这样

向左滑动卡片 → 露出 76vp 的删除块 → 点击 → 确认弹窗

二、改了什么

位置改动原因
列表容器 Scroll + Column → List + ListItem swipeAction 只能挂在 ListItem 上；原来的 Column 里没有列表语义，也就没有左滑
卡片 .swipeAction({ end: this.swipeDelete(item) }) 左滑露出右侧操作区，回弹与「同时只开一个」由框架处理
删除块 76vp 红底 + 垃圾桶图标 + 「删除」 和卡片同圆角（20），左边留 10vp 缝隙，避免糊成一片
菜单 移除「删除音源」项 避免两个入口并存，单点直达更容易误触
确认 AlertDialog：标题「删除音源」+ 说明脚本文件一并删除 删除会 unlink 脚本，只能重新导入，必须有二次确认
提示文案 「…左滑卡片可删除」 左滑是隐藏手势，不加提示没人会发现

三、两个边界

选择模式下不启用 防误删

  • swipeDelete 在 selectMode 时返回 0 宽，滑了也不会露出按钮；
  • 此时横向手势容易和多选冲突，而且「正在挑要导出的源」时误删代价最大；
  • confirmRemove 里再守一道：选择模式直接返回。

点击卡片仍然是切首选 不受影响

  • 左滑是水平手势，点击是竖直之外的独立判定，两者不冲突；
  • 卡片内的开关、菜单按钮照旧可点；
  • 删除完成后 repo.remove() 会重排 order、同步首选、落盘并广播刷新。
