指示器「蓄力冲刺」与「回弹再跳」的成因

这两下怪动作不是手感调参问题，是时序问题：一个出在拖动过程中的补间，一个出在松手之后的归位时机。 下面把两条时间轴摊开对照。

问题一 · 一滑动就「先蓄力、后猛冲」拖动中

指示器每帧都会收到一个新位置，但外面还套着一层 120ms 缓动。新目标一来，缓动被打断、从当前值重新开始， 结果它永远只走完「到目标的一小段」。手指匀速滑动时，这个差值不断累积，指示器就越落越远； 等手指停了、目标不再变，它才把剩下的距离一口气跑完 —— 看着就是先慢慢蹭、再突然冲刺。

修复前 · 补间 120ms 越追越远

修复后 · 拖动中补间 = 0 完全重合

补间只保留在「松手归位」和「点按切页」两个场景，那里需要平滑；手指还按着的时候一律 0 延迟。

问题二 · 快到目标页时「回弹一下、再跳过去」松手后

手指离开后，Swiper 还要自己跑 300ms 的翻页动画，中途不再回调任何拖动事件。原来的兜底归位只等 120ms：它以为滑完了，先把指示器拉回旧页；等 300ms 动画结束、页面真的翻过去，指示器又被搬到新页。 半格 → 旧页 → 新页，就是那下回弹。

修复前 · 120ms 就归位 抢在动画前面

修复后 · 等 onAnimationEnd 动画停，指示器停

松手后的位置不再由定时器猜，改由 Swiper 的 onAnimationEnd 给准确页码；定时器只留 340ms 兜底。

补丁 · 上一版为什么还是回弹第三次

前两处改的是「什么时候跟、什么时候停」，都对了。但还有一个更直接的问题：算出来的位置本身会往回跳， 而我对它的处理方式，恰好把跳变变成了一次可见的后退。

异常值：算出 1.2 格，但手指其实还在第 2 格

两个漏洞

一、异常值「跟一半」
上一版遇到整格跳变时，让它最多走 0.5 格 —— 这个动作本身就是一次后退。 本意是抹平跳变，结果把「不该动」变成了「退半格」。

二、松手后还在读位移
onGestureSwipe 在收尾阶段仍会回调，那时给的偏移量已经不是手指位置。用手指有没有按在屏幕上做门控， 松手后一律不听。

改动清单

位置改动
Shell.ets 订阅 tabDrag；指示器动画时长改为 dragging ? 0 : 200，拖动中零延迟。
Index.ets 拖动首帧广播 tabDrag = true；新增 settleSwipe() 统一落位，先退出拖动再改位置，让归位走补间。
Index.ets 接 onAnimationEnd，翻页动画一停就把指示器落到该页；兜底定时器 120ms → 340ms。
Index.ets onChange 不再无条件写位置：拖动中交给 onAnimationEnd，避免中途被拉回整数。
Index.ets pushSwipe() 遇到单帧超过 0.3 格的跳变整帧丢弃，不再「跟一半」（跟一半就是往回退半格）。
Index.ets .onTouch() 标记手指是否在屏幕上：onGestureSwipe 只在按住时生效，松手后残余回调一律忽略。
Index.ets 兜底归位 340ms → 520ms，给翻页动画加补间留出余量。
一句话：手指在屏幕上时，位置只跟手指；手指离开后，位置只跟 Swiper 的动画结束时刻； 算错的那一帧整帧不要。这三段以前分别掺了「补」「猜」「跟一半」。
