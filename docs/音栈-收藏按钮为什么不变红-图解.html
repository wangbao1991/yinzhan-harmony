小心心点了不红，但其实已经收藏了

不是收藏失败，是「界面没收到状态变化」。根因是一个按值传参的 @Builder。

一句话结论 底排四个按钮共用一个 actionButton(icon, label, active, action) 的带参 Builder。参数是拷贝进来的普通值，this.favorite 改成 true 之后，Builder 内部拿到的仍是参与构建时的旧值 —— 所以心不变红、文案不变「已收藏」，而收藏本身早就写进库里了。

状态是怎么断掉的

改前

点击小心心→ Library.toggleFavorite() 成功→ this.favorite = true→ actionButton 收到的是构建时拷贝的 false→ 图标 / 文案不重新赋值，界面毫无变化

ArkUI 的 @Builder 按值传参不会建立依赖：父组件状态变了，Builder 内部节点不会跟着刷新。所以「数据对了、界面没动」。

改前 · 值传参

收藏 / 音质 / 下载三个按钮全部受影响：切音质标签不变、下载完成图标不变，都是同一个病。

改后 · 无参 Builder

每个按钮各自一个 Builder，状态判断写在内部直接读 this.favorite / this.downloadState，状态一变就重算，并加了 180ms 颜色过渡。

// 改前：传进去的是「值」 this.actionButton(this.favorite ? heart_fill : heart, this.favorite ? '已收藏' : '收藏', this.favorite, () => { … }) @Builder actionButton(icon: Resource, label: string, active: boolean, action: () => void) { … } // 改后：Builder 内部直读 @State @Builder favButton() { SymbolGlyph(this.favorite ? $r('sys.symbol.heart_fill') : $r('sys.symbol.heart')) .fontColor([this.favorite ? this.p().primary : this.onBgSmall()]) Text(this.favorite ? '已收藏' : '收藏') … .onClick(() => { this.toggleFavorite(); }) }

顺带做的两件事

改动为什么
播放页「更多」去掉「收藏到我喜欢」 底排已经有一级收藏按钮，同一屏两个入口做同一件事；状态还不同步时，用户会以为其中一个坏了。给 SongMenu 加 hideFavorite，只在播放页传 true，其它页面（搜索、歌单、歌手页）保留。
toggleFavorite() 改为回读库状态 以前信任 toggleFavorite 的返回值；现在统一用 Library.isFavorite() 回读 —— 就算「我喜欢」超过 500 首被裁掉，界面也和库里真实状态一致，不会出现「心是红的但列表里没有」。
