# 编译环境搭建手册 · 音栈（HarmonyOS 原生音乐应用）v1.0

> 用途：交给另一个 AI，从零复现这套命令行编译 / 签名 / 自检环境。
> 工程：ArkTS + ArkUI，Stage 模型，API 12（HarmonyOS 5.0.0），无第三方依赖。
> 包名 `com.yinzhan.music`，版本 `1.0 / 1`。
> 标注「实测」= 本机确实是这个状态；「官网」= 华为文档要求；「历史」= 本会话实际用过的下载地址。

## 六、签名

`scripts/sign_hap.sh` 内容（参数：输入 HAP、输出 HAP）：

```bash
#!/usr/bin/env bash
set -euo pipefail
: "${OHOS_SDK_LIB:?请设置为 SDK 的 toolchains/lib 目录}"
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
SIGN_DIR="$SCRIPT_DIR/../signing"
IN_FILE="${1:-$SCRIPT_DIR/../entry/build/default/outputs/default/entry-default-unsigned.hap}"
OUT_FILE="${2:-$SCRIPT_DIR/../entry-default-signed.hap}"

java -jar "$OHOS_SDK_LIB/hap-sign-tool.jar" sign-app \
  -mode localSign \
  -keyAlias "openharmony application release" \
  -keyPwd 123456 \
  -appCertFile "$SIGN_DIR/app-chain.pem" \
  -profileFile "$SIGN_DIR/profile.p7b" \
  -inFile "$IN_FILE" \
  -signAlg SHA256withECDSA \
  -keystoreFile "$OHOS_SDK_LIB/OpenHarmony.p12" \
  -keystorePwd 123456 \
  -outFile "$OUT_FILE" \
  -compatibleVersion 12 \
  -signCode 1

java -jar "$OHOS_SDK_LIB/hap-sign-tool.jar" verify-app \
  -inFile "$OUT_FILE" \
  -outCertChain "${OUT_FILE%.hap}-chain.cer" \
  -outProfile "${OUT_FILE%.hap}-profile.p7b"
```

调用：

```bash
cd /workspace/LXMusicHarmony
export OHOS_SDK_LIB=/root/.codebuddy/artifact/hmos/clt/command-line-tools/sdk/default/openharmony/toolchains/lib
bash scripts/sign_hap.sh \
  entry/build/default/outputs/default/entry-default-unsigned.hap \
  /workspace/音栈-v1.0-signed.hap
# 期望输出：verify: Verify success / verify-app success
```

`OpenHarmony.p12` 里的别名（口令统一 `123456`）：

| 别名 | 用途 |
| --- | --- |
| `openharmony application release` | 签 HAP |
| `openharmony application profile release` | 签 Provision Profile |
| `openharmony application profile debug` | 调试 profile |
| `openharmony application ca` / `root ca` | 证书链 |
| `openharmony software signature` | 其它 |
| `cacert` / `rootcacert` | 信任证书 |

### ⚠️ 改 bundleName 必须重签 profile.p7b

`profile.p7b` 里写死 `bundle-info.bundle-name`，安装时系统拿它和 HAP 的 `bundleName` 比对；只改 `app.json5` 不改 p7b 会**拒装**，且 `verify-app` 未必报错。重签命令：

```bash
LIB=/opt/command-line-tools/sdk/default/openharmony/toolchains/lib
TOOL="$LIB/hap-sign-tool.jar"

# 1. 从旧 p7b 导出内容，只改 bundle-name，其余（uuid / 有效期 / 分发证书）原样保留
java -jar "$TOOL" verify-profile -inFile signing/profile.p7b -outFile /tmp/orig.json
python3 - <<'PY'
import json
d = json.load(open('/tmp/orig.json', encoding='utf-8'))['content']
d['bundle-info']['bundle-name'] = 'com.yinzhan.music'
json.dump(d, open('signing/profile.json','w',encoding='utf-8'), ensure_ascii=False, indent=2)
PY

# 2. 重签
java -jar "$TOOL" sign-profile -mode localSign \
  -keyAlias "openharmony application profile release" -keyPwd 123456 \
  -profileCertFile "$LIB/OpenHarmonyProfileRelease.pem" \
  -inFile signing/profile.json -signAlg SHA256withECDSA \
  -keystoreFile "$LIB/OpenHarmony.p12" -keystorePwd 123456 \
  -outFile signing/profile.p7b

# 3. 验签
java -jar "$TOOL" verify-profile -inFile signing/profile.p7b -outFile /tmp/verify.json
```

> 正式华为真机（HarmonyOS NEXT）可能要求 AGC 调试证书，需要用 DevEco Studio 按包名生成调试 profile 后重签；上面这套是 OpenHarmony 公共签名材料，与本机历次交付一致。

## 七、自检与版本核对

```bash
cd /workspace/LXMusicHarmony
python3 scripts/selfcheck.py
# 期望：共 21 项：PASS 17 / WARN 4 / FAIL 0

# 包内版本双向核对（两个文件必须一致）
unzip -p entry/build/default/outputs/default/entry-default-unsigned.hap pack.info \
  | python3 -c "import sys,json;d=json.load(sys.stdin)['summary']['app'];print(d['bundleName'],d['version'])"
unzip -p entry/build/default/outputs/default/entry-default-unsigned.hap module.json \
  | python3 -c "import sys,json;d=json.load(sys.stdin)['app'];print(d['bundleName'],d['versionCode'],d['versionName'])"

# 签名后 HAP 内 profile 的 bundle-name 也要一致
java -jar "$OHOS_SDK_LIB/hap-sign-tool.jar" verify-profile \
  -inFile "/workspace/音栈-v1.0-signed-profile.p7b" -outFile /tmp/v.json
python3 -c "import json;d=json.load(open('/tmp/v.json'));print(d['verifiedPassed'],d['content']['bundle-info']['bundle-name'])"
```

`selfcheck.py` 的 21 项是把历史事故固化成静态扫描（A 广播闭环 / B 死 @Builder / C 带参 Builder / D 页面订阅 / E 回调漏传 / F 监听泄漏 / G 列表 key / H 弹层冲突 / I 加载态收口 / J 系统任务释放 / K 持久化窗口 / L 自动切歌 / M 进度落盘 / N 恢复进度 / O 本地删除安全 / P 下载取消 / Q 重复入口）。**WARN 4 是已知设计豁免，不需要修**。

## 十一、给另一个 AI 的关键注意事项

1. **不用装 ohpm 依赖**。工程 `oh-package.json5` / `entry/oh-package.json5` / `hvigor-config.json5` 的依赖全为空，hvigor 插件内置在 clt。直接 `hvigorw assembleHap` 就能过，离线也行。
2. **不用单独下 SDK**。`commandline-tools-linux-x64-*.zip` 里已嵌 `sdk/default`（hms + openharmony）。那个 2.6 GB 的 `ohos-sdk-windows_linux-public.tar.gz` 是本会话早期探索时下的，**解压都没解压、构建没用到**，别重复下。
3. **JDK 版本**：官网写只支持 17，本机 20 也成功。建议装 17 对齐文档；若沿用 20，出问题时先怀疑 JDK。
4. **`build-profile.json5` 的 `signingConfigs` 为空**，所以 hvigor 产出的是 `entry-default-unsigned.hap`，签名必须走 `scripts/sign_hap.sh` 单独做。日志里 `Will skip sign 'hos_hap'` 是正常现象。
5. **两个构建脚本不一样**：工程内 `scripts/build.sh` 是 debug + 需 `COMMANDLINE_TOOL_DIR`；本会话实际用 `/tmp/build.sh`（release + 写死路径）。交付 HAP 用 release 版，脚本内容见第五节，需要自己重建到 `/tmp/build.sh` 或任意位置。
6. **每版都 `rm -rf entry/build` 再构建**，然后核对 `pack.info` 与 `module.json` 的 bundleName / versionCode / versionName 双向一致。
7. **改 `bundleName` 必须重签 `profile.p7b`**（第六节），否则真机拒装。同时 `signing/profile.json` 要与 p7b 保持同源。
8. **真机安装**：`hdc` 在 `sdk/default/openharmony/toolchains/hdc`，不在 PATH；命令 `hdc install -r <hap>`。HarmonyOS NEXT 正式机可能需要 AGC 调试证书重签。
9. **改包名的副作用**：不能覆盖安装、旧数据不迁移、`.js` 默认打开关联失效。
10. **数据源接口会变**：这些是第三方非公开接口，随时可能限流或失效。测试时带 `Referer` 和 `UA`，QQ `musicu.fcg` 注意 2001 限流码。
11. **交付流程固定**：干净构建 → 签名 → verify-app → 双向版本核对 → selfcheck（FAIL 0）→ 更新文档 → 重打 zip → `md5sum` 比对交付 HAP 与 `/tmp` 产物一致。
12. **预览图**用 chromium headless 渲染的示意图，不是真机截图，不参与构建。
