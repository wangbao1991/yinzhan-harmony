自检收口与本地导入

去掉结论不可靠的「快速体检」，启动自检跑完整自检并在任意页面弹结果；导入明确走本机文件。

一句话：自检只剩一个口径；启动自检在后台静默跑完，只回写音源卡片。 之前三件事叠在一起：快速体检说「通过」但点歌还是失败；启动自检的结论没人看见；导入失败只报四个字「导入失败」。中间那版做成了弹窗，但弹窗会打断正在听歌的用户，本轮已撤掉。

一、为什么砍掉「快速体检」

快速体检 已移除

  • 每源只试第一首匹配平台的基准曲，成功就 break
  • 只证明「至少有一首能取」，不证明其它平台能取
  • 超时压到 8 秒，独家源这类要先拉 rconfig 的必然被判死
  • 和卡片上的「自检」是两套口径，用户对不上

现在的两条路径 同源结论

  • 单源「自检」：卡片菜单里，只测这一个源
  • 「全部自检」：对每个已启用源跑同一套逻辑
  • 逐平台试基准曲、超时 12s，成功即停、失败换下一个平台
  • 跑完给出「可用几个 / 失败几个 / 各自为什么」
耗时怎么补回来：完整自检比体检慢，所以并发开到 3，并加了「脚本级错误短路」—— 报「未注册 request 处理器 / 音源未加载 / 初始化失败」时不再换平台重试。 这类错换哪个平台都一样，死源从 3×12s 降到 1×12s。

二、启动自检：后台跑，静默收口

启动 8 秒后 maybeAutoCheck()
→
checkAll() 并发 3 跑完整自检
→
结果写回 SourceItem.status / message
→
音源页卡片显示状态点与原因

撤掉的版本 会打断播放

  • 跑完用 AppStorage 广播，Index 弹 AlertDialog
  • 自检是后台任务，用户可能正在听歌、正在搜索
  • 十几行失败原因糊在屏幕中央，还得手动关掉

现在的做法 静默

  • 跑完只写一行 console.info
  • 结果回写到每张卡片的状态点、原因、耗时
  • 想看结论就进音源页，不想看就不打扰
为什么不干脆不跑：启动自检的价值是「提前把死源标出来」，让卡片上的状态在用户点歌之前就是准的。 它需要存在，但不需要刷存在感——结论放在用户会去看的地方（音源页），而不是砸在他正看的屏幕上。

两道闸没变：同一进程只跑一次；距上次不足 30 分钟跳过。启动自检是真实取链，连续重启不该变成连续打后端。

三、导入脚本 → 本地导入

项目之前现在
按钮文案「导入脚本」，和「网络导入」并排「本地导入」，和「网络导入」语义对齐
一次可选4 个20 个，换一批源不用来回点
空文件当成导入失败指出「「xxx.js」是空文件」
读取失败统一「导入失败」指出具体文件 + 原因，并提示「如果它在云盘请先下载到本机」
为什么单独提云盘：系统的文件选择器会把云盘、在线的条目也列出来， 但音源脚本必须落盘到应用沙箱才能加载。用户看到文件明明在那儿，点导入却失败， 以前只会得到「导入失败」四个字，很容易以为应用坏了。

四、这轮守住的四条线

自检项判据被抓到的退化
V · 自检收口checkAll 返回 CheckSummary；无 full / quick 参数；页面无「快速体检」快速模式回潮 / 两套结论
V · 静默收口启动自检不广播（无 publishCheckReport / sourceCheckReport）；Index 不监听 sourceCheckVersion弹窗回潮，打断播放
X · 本地导入文案为「本地导入」且无「导入脚本」残留；走系统选择器；含云盘提示文案回退 / 失败原因说不清
A · 广播闭环补认 AppStorage.get<T>('key') 这种取值读法把 sourceCheckReport 误报成冗余广播

反向验证：把 publishCheckReport 挂回启动自检，V 组立刻报「启动自检又在广播结果，弹窗已被要求移除」； 把空态文案改回「导入脚本」，X 组报「页面还残留「导入脚本」文案」。还原后 28 项 PASS 24 / WARN 4 / FAIL 0。

五、装上之后怎么用

首次整理源

  • 先本地导入一批脚本（可多选）
  • 点全部自检，等它跑完
  • 把失败且原因写「403 / 初始化超时」的源左滑删掉

日常

  • 打开启动时自动自检，8 秒后后台跑
  • 跑完不打扰；进音源页看卡片状态
  • 30 分钟内重启不会重复跑，避免打后端
